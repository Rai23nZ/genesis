# Генеалогическое древо

Сервис семейного архива: построение и просмотр древа, карточки людей, карта мест
проживания, очередь модерации правок, импорт GEDCOM/JSON, экспорт резервной
копии, печать древа на листах A4. Клиент — статика без сборки, сервер — Bun и
SQLite.

Репозиторий содержит только код сервиса. Записей о людях, фотографий, учётных
данных и паролей в нём нет и быть не должно — они хранятся в базе на сервере
(см. `server/host/README.md`).

---

## 1. Состав

| Файл | Назначение |
|---|---|
| `index.html` | Точка входа, подключение зависимостей, стили печати |
| `config.js` | Конфигурация клиента: адрес API. Секретов не содержит |
| `app.js` | Приложение: древо, карточка, модерация, импорт, печать (React без сборки) |
| `family-data.js` | Загрузка и синхронизация данных, раскладки, парсеры, экспорт |
| `world-map.js` | Веб-компонент `<family-map>`: карта мест на d3-geo |
| `styles.css` | Токены и компоненты оформления: палитра «Хроника Эпох», фактура бумаги, сургучные печати, анимации |
| `data/sample.json` | Синтетический набор для локального запуска |
| `data/places.json` | Справочник координат для карты: названия мест из архива |
| `tools/vendor.sh` | Загрузка зависимостей в `vendor/` с проверкой хэшей |
| `vendor/` | Локальные копии React, d3, topojson, топологии карты и шрифтов (в git не хранятся) |
| `docs/deployment.md` | Решения по серверной части и порядок работ |
| `docs/audit.md` | Известные слабые места кода и порядок их устранения |

Серверная часть (API, база, CLI, скрипты развёртывания) в репозиторий не
выкладывается и хранится отдельно: репозиторий содержит код клиента и его
документацию. Сторонние библиотеки тоже не хранятся здесь — их скачивает
`tools/vendor.sh`.

## 2. Требования

- Любой статический веб-сервер — сборка не требуется.
- Браузер с поддержкой ES-модулей.
- Открывать по `http(s)://`. Через `file://` не работает: браузер блокирует
  `import` и `fetch` по CORS.

## 3. Запуск

Зависимости лежат локально, поэтому один раз нужно их скачать:

```
./tools/vendor.sh
```

Скрипт кладёт React, d3, topojson, топологию карты и шрифты в `vendor/`,
проверяя хэши SHA-384. Без него интерфейс откроется, но будет набран
запасными системными шрифтами: `styles.css` подключает Bitter и Manrope
только из `vendor/`, к сторонним CDN клиент не обращается вовсе.
Дальше — любой статический сервер:

```
python3 -m http.server 8080
# либо
npx serve .
```

Открыть `http://localhost:8080/`. Без сервера приложение работает в
демонстрационном режиме на `data/sample.json`.

Установка серверной части описана в её собственном `README.md`, который лежит
вместе с ней.

## 4. Конфигурация

`config.js`:

| Ключ | Значение | Смысл |
|---|---|---|
| `apiBase` | `""` | Сервера нет: демонстрационный режим на `data/sample.json`, запись и вход недоступны |
| `apiBase` | `"https://<host>"` | Рабочий режим: данные, вход и правки идут через API |
| `fallbackTitle` | строка | Заголовок до того, как название придёт с сервера |

На сервере этот файл не используется: `deploy.sh` собирает свою копию из
`DOMAIN` и отдаёт её отдельным маршрутом, минуя рабочую копию репозитория.
Секретов в нём нет и быть не может — все проверки доступа выполняет сервер.

## 5. Данные

- Источник истины — сервер. Клиент читает `GET /api/archive` при каждой загрузке
  страницы и после каждой операции записи.
- В `localStorage` не сохраняется ничего: кеш браузера не является хранилищем.
- Без `apiBase` клиент читает `data/sample.json` и помечает интерфейс меткой
  «демо». Изменения в этом режиме живут только в памяти вкладки.
- Импорт принимает `.json` (формат экспорта) и `.ged` (GEDCOM). Название архива
  берётся из поля `title` (JSON) или строки `1 FILE` блока `HEAD` (GEDCOM).
  При подключённом сервере файл разбирает он: сначала показывает отчёт — сколько
  записей принято, что отклонено, кто помечен живущим — и пишет в базу только
  после подтверждения. Без сервера импорт живёт в памяти вкладки до перезагрузки,
  и интерфейс об этом предупреждает.
- Экспорт выгружает `.json` с людьми, местами, очередью модерации и названием.
- Фотография хранит точку кадрирования (`focus`): щелчок по снимку в правке
  назначает место, которое останется в кадре. Карточка на древе почти
  квадратная, галерея вытянутая, и центр по умолчанию режет не всякий портрет.
  Добавлять снимки может и родственник, убирать и перекадрировать — только
  модератор.
- При импорте выставляется признак «живущий»: нет даты смерти и меньше 110 лет —
  считается живущим, человек без обеих дат тоже. Живущие гостям не отдаются.

Контракт API и схема базы описаны в `docs/deployment.md`, разделы 4 и 5.

## 6. Роли

| Роль | Как получает доступ | Что видит |
|---|---|---|
| Гость | без входа | Карточки ушедших; живущие не отдаются сервером |
| Родственник | код приглашения от модератора | Полные карточки; правки и новые люди идут в очередь модерации, фотографии сохраняются сразу |
| Модератор | учётная запись, заводится владельцем архива | Полные карточки, правка без очереди, добавление и удаление людей, очередь, импорт, выдача кодов |

Роль определяется сессией на сервере. Переключатель ролей в интерфейсе только
отражает выданную сессию и не повышает права.

## 7. Адрес страницы

Вид кодируется в адресе, поэтому ссылкой можно поделиться, её можно положить
в закладки, а кнопки «назад» и «вперёд» возвращают то, что было.

| Параметр | Значение | Смысл |
|---|---|---|
| `v` | `ring` / `river` | Вид «Круг рода» или «Река времени». По умолчанию древо, в адрес не пишется |
| `p` | `id` человека | Открыть карточку; в круге он же встаёт в центр |
| `q` | строка | Поисковый запрос |
| `z` | `0.35`–`1.5` | Масштаб полотна |
| `map` | `all` / `route` | Открыть карту в этом режиме |
| `route` | `id` человека | Маршрут переселений для карты |

Пример: `?p=I14&z=1.10` — карточка Александра Васильевича при масштабе 110%.
Значения по умолчанию в адрес не пишутся. Выбор человека добавляет запись
в историю, поиск и масштаб правят текущую. Если человека из ссылки в архиве
нет (запись удалена или это живущий, которого гостю не отдали), интерфейс
сообщает об этом и показывает древо целиком.

## 8. Виды

Один архив, несколько взглядов. Вид переключается в шапке и попадает в адрес.

| Вид | Отвечает на вопрос | Когда нужен |
|---|---|---|
| Древо | Кто кому кем приходится | Разбор структуры, правки, печать |
| Круг рода | Каких предков мы не знаем | Планирование работы в архиве |
| Река времени | Когда они жили и что застали | Рассказ об истории рода |
| Карта | Откуда и куда двигался род | Поиск земляков и метрических книг |

«Круг рода» раскладывает прямых предков выбранного человека на три колена:
кольцо — поколение, место в кольце — определённый предок (нумерация
Соса-Страдоница, отец в `2i`, мать в `2i+1`). Пустой сектор означает, что
предок неизвестен, и это основное содержание вида: список того, что искать.
Золотая дуга у внутреннего края сектора показывает, насколько полна карточка.
Щелчок по предку ставит его в центр — и добавляет запись в историю, поэтому
«назад» возвращает к прежнему корню.

«Река времени» кладёт людей отрезками жизни на общую ось лет: сразу видно,
кто кого застал, кто сколько прожил и чья молодость пришлась на войну. Точные
даты залиты сплошь, приблизительные («ок. 1898», «до 1965») растворяются по
краям, а записи без единой даты нарисованы пунктиром — их границы выведены из
дат детей, супруга или родителей и достоверными не считаются. Фоном наложены
полосы эпох. Люди сгруппированы по роду: `Ветров` и `Ветрова` попадают в одну
строку, поэтому вышедшая замуж женщина видна в роду мужа.

Печать собирает листы из полотна древа, поэтому в остальных видах её кнопка
выключена.

## 9. Ограничения текущей версии

- Экспорт выгружает то, что видит текущая роль; полный бэкап с очередью
  модерации снимается на сервере.
- Двое модераторов не видят решения друг друга без перезагрузки страницы.
- Координаты мест задаются справочником `data/places.json`: ни в GEDCOM, ни в
  выгрузках их нет, поэтому без него карта пуста.
