# Генеалогическое древо — веб-клиент

Клиентская часть сервиса семейного архива: построение и просмотр древа, карточки
людей, карта мест проживания, очередь модерации правок, импорт GEDCOM/JSON,
экспорт резервной копии, печать древа на листах A4.

Репозиторий содержит только код сервиса. Записей о людях, фотографий, учётных
данных и адресов серверов в нём нет и быть не должно — они хранятся в базе на
сервере (см. `docs/deployment.md`).

---

## 1. Состав

| Файл | Назначение |
|---|---|
| `index.html` | Точка входа, подключение зависимостей, стили печати |
| `config.js` | Конфигурация клиента: адрес API. Секретов не содержит |
| `app.js` | Приложение: древо, карточка, модерация, импорт, печать (React без сборки) |
| `family-data.js` | Загрузка и синхронизация данных, раскладки, парсеры, экспорт |
| `world-map.js` | Веб-компонент `<family-map>`: карта мест на d3-geo |
| `styles.css` | Токены и компоненты оформления |
| `data/sample.json` | Синтетический набор для локального запуска |
| `docs/deployment.md` | План развёртывания серверной части |
| `docs/audit.md` | Известные слабые места кода и порядок их устранения |

## 2. Требования

- Любой статический веб-сервер (nginx, Apache, Caddy) — сборка не требуется.
- Браузер с поддержкой ES-модулей.
- Открывать по `http(s)://`. Через `file://` не работает: браузер блокирует
  `import` и `fetch` по CORS.

## 3. Запуск

```
python3 -m http.server 8080
# либо
npx serve .
```

Открыть `http://localhost:8080/`.

## 4. Конфигурация

`config.js`:

| Ключ | Значение | Смысл |
|---|---|---|
| `apiBase` | `""` | Сервера нет: демонстрационный режим на `data/sample.json`, запись и вход недоступны |
| `apiBase` | `"https://<host>"` | Рабочий режим: данные, вход и правки идут через API |
| `fallbackTitle` | строка | Заголовок до того, как название придёт с сервера |

Файл подменяется при развёртывании и не должен содержать секретов: все проверки
доступа выполняет сервер.

## 5. Данные

- Источник истины — сервер. Клиент читает `GET /api/archive` при каждой загрузке
  страницы и после каждой операции записи.
- В `localStorage` не сохраняется ничего: кеш браузера не является хранилищем.
- Без `apiBase` клиент читает `data/sample.json` и помечает интерфейс меткой
  «демо». Изменения в этом режиме живут только в памяти вкладки.
- Импорт принимает `.json` (формат экспорта) и `.ged` (GEDCOM). Название архива
  берётся из поля `title` (JSON) или строки `1 FILE` блока `HEAD` (GEDCOM).
- Экспорт выгружает `.json` с людьми, очередью модерации и названием.

Контракт API и схема базы описаны в `docs/deployment.md`, разделы 4 и 5.

## 6. Роли

| Роль | Как получает доступ | Что видит |
|---|---|---|
| Гость | без входа | Карточки ушедших; живущие не отдаются сервером |
| Родственник | код приглашения от модератора | Полные карточки; правки идут в очередь модерации |
| Модератор | учётная запись, заводится владельцем архива | Полные карточки, очередь, импорт/экспорт, выдача кодов |

Роль определяется сессией на сервере. Переключатель ролей в интерфейсе только
отражает выданную сессию и не повышает права.

## 7. Ограничения текущей версии

- Серверная часть в этом репозитории отсутствует: без `apiBase` приложение
  работает как просмотрщик демонстрационных данных.
- React, ReactDOM, d3 и topojson загружаются с `unpkg.com` (с проверкой SRI),
  топология карты — с `cdn.jsdelivr.net`. Переход на локальные копии — пункт 8.4
  плана развёртывания.
- Загруженные в браузере фотографии существуют как `blob:`-ссылки до
  перезагрузки страницы; постоянное хранение появляется вместе с API.
