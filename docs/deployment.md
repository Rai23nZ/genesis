# План перевода на серверное хранение

Документ описывает, как перевести приложение с чтения локального файла на работу
с сервером: собственная база, учётные записи, постоянное хранение фотографий и
синхронизация всех изменений. Работы ведутся на временном контуре и переносятся
на рабочий домен по чек-листу раздела 9.

Во всех примерах: `example.org` — рабочий домен, `dev.example.org` — временный,
`<VPS-IP>` — адрес сервера. Настоящие адреса, логины и пароли в репозиторий не
попадают ни при каких условиях.

---

## 1. Что меняется по существу

| | Сейчас | После перехода |
|---|---|---|
| Хранение | Массив в памяти вкладки | SQLite на сервере, файл на диске VPS |
| Правки | Исчезают при `F5` | Запись в базу, очередь модерации переживает перезагрузку |
| Фотографии | `blob:`-ссылка до закрытия вкладки | Файл на диске, отдаётся через авторизованный маршрут |
| Вход | Отсутствует | Сессия на сервере: коды приглашений и пароли модераторов |
| Скрытие живущих | Фильтр в интерфейсе поверх полных данных | Сервер не кладёт эти записи в ответ |
| Синхронизация | Нет | Единый источник: клиент перечитывает архив после каждой операции |

## 2. Целевая архитектура

```
браузер
  └─ https://example.org            статика (index.html, app.js, styles.css)
       └─ /api/*        → nginx → 127.0.0.1:8081 (Node.js)
                                     ├─ SQLite (WAL)         /srv/family-tree/var/archive.sqlite
                                     └─ файлы фотографий     /srv/family-tree/var/uploads/
```

| Компонент | Выбор | Обоснование |
|---|---|---|
| Среда | Node.js 20 LTS | Клиент уже на JS; общий словарь моделей с фронтендом |
| HTTP | Express + `helmet`, `express-rate-limit` | Минимальный слой, весь код обозрим |
| База | SQLite в режиме WAL | Один VPS, десятки пользователей. Бэкап — копия файла |
| Пароли | argon2id (`argon2`) | Хранится только хэш; сравнение с открытым текстом исключено |
| Сессии | Записи в таблице `sessions` + cookie | Доступ отзывается мгновенно, в отличие от JWT |
| Фото | Файлы на диске + `sharp` для превью | В базе только метаданные; каталог вне webroot |

Бэкенд слушает `127.0.0.1` и наружу не публикуется никогда — только через nginx.

## 3. Раскладка на диске

```
/srv/family-tree/
├── web/                  статика из этого репозитория
│   └── config.js         apiBase: "" (один домен с API)
├── server/               код бэкенда (отдельный репозиторий или каталог server/)
│   ├── src/
│   └── package.json
├── var/
│   ├── archive.sqlite    база
│   ├── uploads/          оригиналы фотографий
│   └── thumbs/           превью
└── .env                  права 600, владелец — сервисный пользователь
```

`.env`: `PORT`, `DB_PATH`, `UPLOAD_DIR`, `SESSION_SECRET`, `COOKIE_DOMAIN`,
`PUBLIC_ORIGIN`, `INVITE_TTL_DAYS=14`, `SESSION_TTL_DAYS=30`. В git не попадает
(см. `.gitignore`).

## 4. Схема базы

| Таблица | Ключевые поля | Комментарий |
|---|---|---|
| `users` | `id`, `email`, `role`, `password_hash`, `created_at`, `disabled_at` | Только модераторы и владелец |
| `invites` | `id`, `email`, `code_hash`, `role`, `expires_at`, `used_at`, `issued_by` | Код хранится хэшем, одноразовый |
| `sessions` | `id`, `user_id`/`invite_id`, `role`, `expires_at`, `revoked_at`, `ip`, `ua` | Отзыв — проставление `revoked_at` |
| `people` | `id`, `name`, `maiden`, `sex`, `gen`, `birth_*`, `death_*`, `living`, `minor`, `occupation`, `employer`, `education`, `military`, `notes`, `version`, `updated_at` | `version` — счётчик для контроля конкурентных правок |
| `relationships` | `person_id`, `related_id`, `kind` (`parent`/`spouse`) | Связи вынесены из карточки |
| `residences` | `person_id`, `place`, `from_year`, `to_year`, `note`, `ord` | Хронология мест |
| `places` | `name`, `lat`, `lon` | Справочник координат для карты |
| `documents` | `person_id`, `kind` (`document`/`source`), `text` | Документы и источники |
| `photos` | `id`, `person_id`, `file`, `thumb`, `caption`, `year`, `status`, `uploaded_by`, `sha256` | Файл на диске, статус модерации |
| `moderation_queue` | `id`, `author`, `role`, `target_id`, `kind`, `summary`, `changes_json`, `patch_json`, `state`, `created_at`, `decided_at`, `decided_by` | Заменяет массив в памяти |
| `settings` | `key`, `value` | Название архива и общие параметры |
| `audit_log` | `id`, `actor`, `action`, `target`, `at`, `ip` | Кто и что изменил — нужно при нескольких модераторах |

Индексы: `people(updated_at)`, `relationships(person_id)`, `photos(person_id)`,
`moderation_queue(state, created_at)`, `sessions(expires_at)`.

## 5. Контракт API

Клиент уже написан под эти маршруты (`family-data.js`).

| Метод | Маршрут | Доступ | Ответ / действие |
|---|---|---|---|
| `GET` | `/api/archive` | любой | `{ title, places, people, moderation }`. Для гостя записи живущих не включаются; `moderation` пуст |
| `POST` | `/api/auth/login` | любой | `{ role }` + установка cookie сессии. `401` при неверных данных |
| `POST` | `/api/auth/logout` | сессия | Проставляет `revoked_at` |
| `POST` | `/api/people/:id/edit` | родственник, модератор | `{ queued: true }` для родственника, `{ queued: false }` для модератора |
| `POST` | `/api/moderation/:id/approve` | модератор | Применяет `patch_json` в транзакции |
| `POST` | `/api/moderation/:id/reject` | модератор | Помечает запись отклонённой |
| `POST` | `/api/people/:id/photos` | родственник, модератор | `multipart/form-data`, до 12 файлов, 15 МБ каждый |
| `GET` | `/api/photos/:id` | по роли | Отдаёт файл после проверки прав. Через nginx напрямую не раздаётся |
| `POST` | `/api/import` | модератор | GEDCOM/JSON, лимит 20 МБ, разбор в транзакции |
| `GET` | `/api/export` | модератор | Полный бэкап `.json` |

Правила ответов:

1. Фильтрация по роли выполняется до сериализации: поля живущих не должны
   попадать в JSON гостя даже в скрытом виде.
2. Все ответы — `Cache-Control: no-store`.
3. Конкурентные правки: клиент передаёт `version` карточки, при несовпадении
   сервер отвечает `409` и клиент перечитывает архив.
4. Ограничения: 60 запросов в минуту на IP на чтение, 10 — на запись,
   5 попыток входа за 15 минут на адрес.

## 6. Доступ и учётные данные

| Роль | Выдача | Срок | Хранение секрета |
|---|---|---|---|
| Владелец/модератор | Учётная запись создаётся CLI-скриптом на сервере | 30 дней сессия | `argon2id`, пароль от 12 символов |
| Родственник | Модератор создаёт код в панели и передаёт лично | 14 дней | `argon2id` от кода, одноразовое использование |
| Гость | Без входа | — | — |

- Cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, срок = сроку сессии.
- Смена пароля и выход отзывают все сессии пользователя.
- Неудачные входы пишутся в `audit_log`; после 5 подряд адрес блокируется на 15 минут.
- Рассылка кодов по e-mail на первом этапе не подключается; SMTP добавляется
  позже без изменения схемы (`invites.email` уже есть).

## 7. Фотографии и синхронизация

1. Приём: проверка сигнатуры файла (не по расширению), лимит 15 МБ, белый список
   `jpeg/png/webp/heic`, пересохранение через `sharp` со снятием EXIF —
   геометки и модель камеры не должны утекать вместе со сканом.
2. Хранение: `var/uploads/<sha256[0:2]>/<sha256>.<ext>`, дубликаты по хэшу не
   плодятся. Превью 320px — в `var/thumbs/`.
3. Выдача: только `GET /api/photos/:id`, с проверкой роли и статуса модерации.
   Каталог `var/` не входит в `root` nginx.
4. Синхронизация: источник истины — сервер; клиент перечитывает `/api/archive`
   после входа, правки и решения модератора. Для очереди модерации на втором
   этапе — `GET /api/moderation/stream` (SSE), чтобы двое модераторов видели
   решения друг друга без перезагрузки.

## 8. Развёртывание на временном контуре

Временный контур — поддомен рабочего домена: `dev.example.org` (A-запись на
`<VPS-IP>` в панели reg.ru). Так проверяются TLS, cookie и nginx ровно в той
конфигурации, что пойдёт в прод, а рабочий адрес остаётся нетронутым.

**8.1. Подготовка сервера**
```
adduser familytree && usermod -aG sudo familytree
ufw allow OpenSSH && ufw allow 80,443/tcp && ufw enable
apt install -y nginx certbot python3-certbot-nginx sqlite3
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs
```
Вход по паролю для root отключить (`PermitRootLogin no`, `PasswordAuthentication no`).

**8.2. DNS**
```
dig +short dev.example.org      # должен вернуть <VPS-IP>
```

**8.3. Код и конфигурация**
```
git clone <repo> /srv/family-tree/web
install -m 600 /dev/null /srv/family-tree/.env   # заполнить значениями
```
В `/srv/family-tree/web/config.js` оставить `apiBase: ""` — API на том же домене.

**8.4. Локальные копии зависимостей**

Скачать React, ReactDOM, d3, topojson и `countries-110m.json` в `web/vendor/`,
заменить ссылки в `index.html`. Это снимает зависимость от unpkg и jsdelivr и
позволяет включить строгий CSP без `unpkg.com` в списке источников.

**8.5. Служба**
```
# /etc/systemd/system/family-tree.service
[Service]
User=familytree
WorkingDirectory=/srv/family-tree/server
EnvironmentFile=/srv/family-tree/.env
ExecStart=/usr/bin/node src/index.js
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/srv/family-tree/var
```

**8.6. nginx**
```
server {
  server_name dev.example.org;
  root /srv/family-tree/web;
  index index.html;

  add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; object-src 'none'; frame-ancestors 'none'; base-uri 'none'" always;
  add_header X-Content-Type-Options nosniff always;
  add_header Referrer-Policy same-origin always;

  location /api/ {
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 20m;
  }
}
```
Каталог `/srv/family-tree/var` в конфигурации не упоминается — фотографии
проходят только через API.

**8.7. TLS**
```
certbot --nginx -d dev.example.org
systemctl list-timers | grep certbot     # автопродление
```

**8.8. Первый модератор**
```
node src/cli/create-moderator.js --email <адрес>    # пароль запрашивается интерактивно
```

**8.9. Наполнение данными**

Импорт реального архива выполняет модератор через интерфейс (`.ged`/`.json`) уже
на сервере. Файл с данными семьи в репозиторий не кладётся.

**8.10. Приёмка временного контура**

| Проверка | Как убедиться |
|---|---|
| Данные переживают перезагрузку | Внести правку, нажать `F5`, правка на месте |
| Гость не получает живущих | `curl https://dev.example.org/api/archive` без cookie — в ответе нет ни одного `living: true` |
| Фото не достаются напрямую | `curl https://dev.example.org/var/uploads/...` → `404` |
| Роль не повышается из браузера | Правка `document.cookie` и полей формы не даёт доступа к очереди |
| Очередь модерации сохраняется | Перезапуск службы, очередь на месте |
| Резервная копия восстанавливается | Развернуть бэкап в чистый каталог и открыть |

## 9. Перенос на рабочий домен

Порядок рассчитан на то, что временный контур остаётся рабочим до последнего
шага и служит точкой отката.

1. **Заморозка.** Модератор прекращает правки, время фиксируется.
2. **Слепок.** `sqlite3 archive.sqlite ".backup /tmp/cutover.sqlite"` и
   `tar czf uploads.tgz var/uploads var/thumbs`. Копия снимается с сервера.
3. **Каталог прода.** `/srv/family-tree-prod/` с тем же деревом; данные
   разворачиваются из слепка.
4. **DNS.** A-запись `example.org` на `<VPS-IP>`; TTL заранее снизить до 300 с.
5. **TLS.** `certbot --nginx -d example.org -d www.example.org`.
6. **Ротация секретов.** Новый `SESSION_SECRET`, `COOKIE_DOMAIN=example.org`.
   Все сессии временного контура становятся недействительны — это ожидаемо.
7. **Переиздание доступов.** Коды приглашений, выданные на `dev.`, отзываются
   (`invites.used_at = now`), родственникам выдаются новые. Пароли модераторов
   меняются на рабочем контуре.
8. **Проверка** по таблице 8.10, но на рабочем адресе.
9. **Закрытие временного контура.** `dev.example.org` переводится в `410 Gone`
   или закрывается basic-аутентификацией; база временного контура удаляется
   после того, как рабочий отработал неделю без замечаний.
10. **Откат.** До шага 9 возврат — это переключение A-записи обратно;
    рабочие данные при этом не теряются, так как слепок снят на шаге 2.

## 10. Резервное копирование

```
0 3 * * *  sqlite3 /srv/family-tree/var/archive.sqlite \
           ".backup /srv/backups/archive-$(date +\%F).sqlite"
15 3 * * * tar czf /srv/backups/uploads-$(date +\%F).tgz -C /srv/family-tree/var uploads thumbs
```
- Хранение 14 ежедневных копий и 6 еженедельных.
- Копия выносится за пределы VPS (объектное хранилище или домашний NAS):
  потеря сервера не должна означать потерю архива.
- Раз в квартал — контрольное восстановление в отдельный каталог.

## 11. Этапы и результат

| Этап | Содержание | Результат |
|---|---|---|
| 1 | База, `GET /api/archive`, фильтрация по ролям | Древо открывается с сервера, живущие не уходят гостям |
| 2 | Сессии, коды приглашений, CLI модератора | Вход работает, роль подтверждается сервером |
| 3 | Правки и очередь модерации | Изменения переживают перезагрузку |
| 4 | Фотографии: приём, хранение, авторизованная выдача | Сканы хранятся постоянно |
| 5 | Импорт/экспорт на сервере, бэкапы, локальные копии зависимостей | Контур готов к переносу |
| 6 | Перенос по разделу 9 | Рабочий домен, временный контур закрыт |

## 12. Что остаётся за рамками первого запуска

- Рассылка кодов по e-mail (SMTP) и уведомления модератора.
- SSE-поток очереди модерации для нескольких модераторов.
- Переход на PostgreSQL — имеет смысл только при заметном росте нагрузки.
- Отдельная страница согласия для живущих родственников на публикацию данных.
