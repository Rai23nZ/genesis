## 2. Изменения структуры

| Было | Стало |
|---|---|
| `family-data.js` — данные и логика в одном файле | Только логика: загрузка (`loadArchive`, `whenReady`), запись (`apiSubmitEdit`, `apiModerate`, `apiLogin`), раскладки, парсеры |
| Данные импортировались статически | Единая точка входа: API сервера → иначе `data/sample.json`. Модуль ES — синглтон, поэтому приложение и карта работают с одним набором |
| Адрес сервера нигде не задавался | `config.js` — единственное место конфигурации, без секретов |

## 4. Незакрытое

### 4.1 Правило доступа для несовершеннолетних

Флаг `minor` есть в модели, сохраняется в базе и правится в карточке, но
отдельного правила доступа под него нет: гостю не отдаются записи `living`, а
несовершеннолетний под это правило попадает лишь потому, что он заведомо живущий.

Закрывать это в клиенте нельзя. Ровно такую ошибку разбирает раздел 3:
«скрытие живущих визуальное» — данные уже лежали в браузере гостя, и фильтр в
интерфейсе был декорацией. Правило должно стоять в `server/host/archive.js`
рядом с фильтром `living` и проверяться запросом в `selftest.js`, а не глазами.

### 4.2 Печать клонирует полотно целиком

Для каждого листа создаётся своя копия полотна. На большом древе это десятки
клонов и заметная пауза. Сейчас интерфейс хотя бы предупреждает («Собираю N
листов…») и не выглядит зависшим, но саму работу это не ускоряет. Лечится
отрисовкой листов из одной копии со смещением фона.

### 4.3 Шапка на узком экране

На телефоне 375×812 шапка занимает 213 пикселей в свёрнутом виде: два ряда
переключателей (роль и вид) плюс поиск. Редкие действия убраны под «Ещё».
Дальше сокращать — только объединяя переключатели ролей и видов в одно меню.
